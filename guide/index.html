ภาค 1

ดึงข้อมูลผ่าน RS-232 — พื้นฐานที่ใช้ได้ทุกเครื่อง

อ่านจบภาคนี้แล้วเดินเข้าไปหาเครื่องอะไรก็ได้ในโรงพยาบาล แล้วเริ่มหาทางคุยกับมันได้

1ทำไมเครื่องมือแพทย์ยังใช้ RS-232 อยู่

RS-232 เป็นมาตรฐานจากยุค 1960 ที่ยังอยู่ในห้องตรวจปี 2569 ไม่ใช่เพราะไม่มีใครอัปเกรด แต่เพราะมันเหมาะกับงานนี้จริง ๆ

  • เครื่องมือแพทย์อายุยืน เครื่องหนึ่งใช้ 10–15 ปี เครื่องที่ซื้อปี 2558 ยังอยู่ในห้องตรวจวันนี้ และตอนออกแบบมันก็เลือกพอร์ตที่จะไม่ล้าสมัย
  • ไม่ต้องมี driver ไม่ต้องจับคู่ เสียบแล้วคุยได้เลย ไม่มีอาการ "วันนี้ Bluetooth ไม่ยอมต่อ"
  • ไม่มีพื้นผิวให้โจมตีแบบเครือข่าย อุปกรณ์ที่ต่อสายตรงไม่โดนสแกนพอร์ต
  • ดีบักได้ด้วยตาเปล่า เปิดโปรแกรมเทอร์มินัลก็เห็นทุกไบต์ที่วิ่ง — ข้อนี้สำคัญมากและจะใช้ตลอดทั้งคู่มือ

แปลว่าทักษะนี้ยังจำเป็นไปอีกนาน และคนที่ทำเป็นมีน้อยกว่าที่ควร

2พื้นฐานที่ต้องรู้จริง ๆ แค่ 5 ข้อ

2.1 สายมีแค่ 3 เส้นที่สำคัญ

หัวต่อ DB9 มี 9 ขา แต่การอ่านค่าจากเครื่องมือแพทย์ใช้จริงแค่ 3 ขา

2.2 สายตรง หรือ สายไขว้ (null-modem)

นี่คือสาเหตุอันดับหนึ่งของอาการ "ต่อแล้วเงียบสนิท"

ถ้าไม่อยากซื้อสายใหม่ ซื้อ null-modem adapter หัวเล็ก ๆ มาเสียบคั่นได้ ราคาไม่กี่สิบบาท และควรมีติดกระเป๋าไว้เลย

2.3 แรงดันไม่เท่า TTL

ห้ามต่อ RS-232 เข้าขา Arduino หรือ Raspberry Pi ตรง ๆ

RS-232 ใช้แรงดันได้ถึง ±12 โวลต์ ส่วนขา GPIO ของบอร์ดพวกนี้รับแค่ 3.3–5 โวลต์ ต่อตรงคือพัง ต้องผ่านตัวแปลงระดับแรงดัน (เช่นโมดูล MAX3232) หรือใช้ตัวแปลง USB-to-Serial ซึ่งจัดการให้อยู่แล้ว

  1. เปิด Device Manager กด Win + X แล้วเลือก Device Manager หรือกด Win + R พิมพ์ devmgmt.msc
  2. ดูหัวข้อ Ports (COM & LPT) ถ้าไม่มีหัวข้อนี้เลย แปลว่าไม่มีพอร์ตอนุกรมในระบบ — ตัวแปลงยังไม่ได้เสียบ หรือไดรเวอร์ยังไม่ลง

  4. ถ้าเลข COM สูงเกินไป บางโปรแกรมเก่ารองรับถึงแค่ COM9 เปลี่ยนได้ที่ Properties → Port Settings → Advanced → COM Port Number

6อุปกรณ์ไม่มีเอกสาร: ถอดรหัสโปรโตคอล 6 ขั้น

สถานการณ์จริงที่เจอบ่อยที่สุด: มีเครื่องอยู่ตรงหน้า ไม่มีคู่มือ ผู้ผลิตไม่ตอบอีเมล ค้นอินเทอร์เน็ตก็ไม่เจอ ยังทำได้ และนี่คือขั้นตอน

  1. ไล่ baud จนไบต์อ่านออก เปิด Hercules โหมด HEX แล้วลองเรียงนี้: 9600 → 19200 → 38400 → 115200 สั่งเครื่องวัด 1 ครั้งในแต่ละค่า
    สัญญาณว่าถูกแล้ว: ไบต์ออกมาเป็นรูปแบบเดิมซ้ำ ๆ ทุกครั้ง มีช่วงที่เป็นตัวเลข ASCII (30–39) สัญญาณว่าผิด: ไบต์มั่วไม่ซ้ำกันเลย ยาวสั้นไม่เท่ากันทุกครั้ง
  2. ดูว่าเครื่องส่งเองหรือต้องขอ วัด 1 ครั้งโดยไม่ส่งอะไรออกไปเลย ถ้ามีข้อมูลไหลออกมา แสดงว่าเครื่องส่งเอง — งานง่ายลงครึ่งหนึ่ง เพราะแค่ดักฟังก็พอ ถ้าเงียบ ต้องหาคำสั่งขอข้อมูล ลอง $05 (ENQ) และ $06 (ACK) ก่อน
  3. หาขอบเฟรม ดูว่าไบต์ชุดเดิมขึ้นต้นและลงท้ายด้วยอะไรทุกครั้ง มองหา 02…03 (STX/ETX) หรือ 0D 0A (CR/LF) ถ้าเจอ แปลว่ารู้แล้วว่าเฟรมเริ่มและจบตรงไหน ซึ่งเป็นครึ่งหนึ่งของงาน
  4. วัดค่าที่รู้คำตอบอยู่แล้ว วัดความดัน 3 ครั้ง จดค่าที่ขึ้นบนหน้าจอเครื่องไว้ทุกครั้ง แล้วหาเลขนั้นในไบต์ ถ้าเครื่องแสดง 138 ให้มองหา 31 33 38 (คือ ASCII ของ '1' '3' '8') นี่คือเทคนิคหลักในการหาว่าฟิลด์ไหนอยู่ตรงไหน
  5. ยืนยันด้วยสูตร MAP
    เทคนิคที่ทรงพลังที่สุดในบทนี้

    ค่าความดันเฉลี่ย (MAP) มีความสัมพันธ์ทางสรีรวิทยากับ SYS และ DIA เสมอ:

    MAP ≈ (SYS + 2 × DIA) / 3

12.1 คำนวณ BCC

บวกทุกไบต์ รวม STX และ ETX แล้วเอาเฉพาะ 8 บิตล่าง

BCC = (ผลรวมของทุกไบต์ตั้งแต่ STX ถึง ETX) & 0xFF

ตัวอย่างเล็กที่ตรวจด้วยมือได้ — เฟรมคำสั่ง D1,

02 44 31 2C 03 → A6
0x02 + 0x44 + 0x31 + 0x2C + 0x03
  2  +  68  +  49  +  44  +   3   = 166 = 0xA6  ✓

ถ้าคำนวณตามนี้แล้วไม่ได้ A6 แปลว่าเข้าใจสูตรผิด ให้กลับมาตรวจตรงนี้ก่อน

จุดแตกหักของโปรเจกต์นี้

ค่าความดันมาพร้อมเฟรมที่เครื่องส่งออกมาเองอยู่แล้ว ไม่ต้องทำ handshake ให้สำเร็จก็อ่านค่าได้ แค่ดักฟังแล้วแยกเฟรมเป็นพอ — ความเข้าใจข้อนี้ทำให้งานที่ค้างอยู่หลายเดือนจบลงได้

21ผูกค่ากับคนไข้แล้วบันทึก

จังหวะที่เสี่ยงบันทึกผิดคนมากที่สุด

ค่าความดันที่ไปอยู่กับคนไข้ผิดคนอันตรายกว่าไม่มีค่าเลย เพราะมันดูน่าเชื่อถือ กฎ 4 ข้อนี้ต้องมีทุกข้อ

  • ล็อก HN ก่อนกดเริ่มวัด ค่าที่เข้ามาหลังจากนั้นผูกกับ HN นั้นเท่านั้น
  • เปลี่ยน HN กลางคัน ต้องล้างค่าที่ค้างอยู่ทิ้งทันที นี่คือทางที่ค่าคนก่อนหน้าจะติดไปกับคนถัดไป
  • ค่าที่เข้ามาโดยยังไม่ได้เลือกคนไข้ ให้พักไว้ ห้ามบันทึกอัตโนมัติ แสดงบนจอได้ แต่ต้องเลือกคนไข้ก่อนถึงจะบันทึกได้
  • มีหน้ายืนยันเสมอ แสดงชื่อ-สกุล คู่กับค่าที่วัดได้ ก่อนกดบันทึก

hn, ชื่อ, วันเวลาที่วัด, SYS, MAP, DIA, PULSE, รหัสเครื่อง, แหล่งที่มา

บันทึกว่าค่านี้มาจากเครื่องอัตโนมัติ (auto) หรือพิมพ์มือ (manual) วันที่มีคนตั้งคำถามว่าตัวเลขนี้เชื่อได้ไหม ฟิลด์เดียวนี้ตอบได้ทันที และยังใช้วัดได้ว่าระบบอัตโนมัติทำงานจริงกี่เปอร์เซ็นต์

21.2 เก็บ MAP ด้วย

เครื่องส่ง MAP มาให้อยู่แล้ว แต่โค้ดทดลองรุ่นแรก ๆ ทิ้งทุกตัว เก็บไว้เถอะ — ไม่มีต้นทุนเพิ่ม และเป็นค่าที่มีความหมายทางคลินิก ถ้าเครื่องไม่ส่งมา คำนวณเองได้ด้วยสูตรเดิม

21.3 ใช้เวลาจากเฟรม ไม่ใช่เวลาของคอมพิวเตอร์

เฟรมมีวันเวลาของเครื่องมาด้วย ใช้ค่านั้น เพราะถ้านาฬิกาเครื่องวัดเพี้ยน เราจะเห็นและแก้ได้ แต่ถ้าเขียนทับด้วยเวลาคอมพิวเตอร์ ปัญหาจะถูกกลบไว้เฉย ๆ นาฬิกาเครื่องวัดเพี้ยนเป็นเรื่องที่เจอบ่อยมาก

แอปค้างที่ "รอข้อมูล" ทั้งที่สายทำงาน ตัวตัดเฟรม ตัวตัดเฟรมรอเฉพาะ \r\n แต่เครื่องจบด้วย ETX ต้องรองรับทั้งสองแบบ (ดูบทที่ 7)
อ่านได้บ้างไม่ได้บ้าง สุ่ม ๆ อ่านทีละไบต์ไม่รอให้ครบเฟรม ต้องสะสมไบต์ลงบัฟเฟอร์จนเจอขอบเฟรมก่อน แล้วค่อยแยก
ฟิลด์แรกเพี้ยน ตรวจชนิดเรคคอร์ดไม่ผ่าน ไม่ได้ตัดไบต์ควบคุม ตัดไบต์ที่ไม่ใช่อักขระอ่านได้ทิ้งก่อน split ไม่งั้น checksum ไบต์สุดท้ายจะติดไปกับฟิลด์แรกของเฟรมถัดไป
checksum ไม่ตรงเป็นบางครั้ง สายรบกวน หรือ baud คาบเส้น เปลี่ยนสายให้สั้นลง เลี่ยงเดินคู่กับสายไฟ ลองลด baud
โปรแกรมพังตอนถอดสาย USB ตัวอ่านพอร์ต บน Windows จำนวนไบต์ที่รออยู่จะคืนค่า -1 เมื่อพอร์ตมีปัญหา ถ้าเอาค่านั้นไปใช้เป็นความยาวบัฟเฟอร์จะพังทันที ต้องกันค่า ≤ 0 ไว้ก่อนเสมอ และอ่านแบบตั้งเวลาถามเป็นช่วง ๆ แทนการผูกเป็นสตรีม
DIA สูงกว่าความจริงราว 15 สลับ index MAP กับ DIA ตรวจด้วยสูตร (SYS + 2×DIA) ÷ 3 — ฟิลด์ที่ตรงกับสูตรคือ MAP ไม่ใช่ DIA
เวลาที่บันทึกไม่ตรงกับเวลาจริง นาฬิกาเครื่องวัด ตั้งนาฬิกาที่ตัวเครื่องใหม่ อย่าแก้ด้วยการเขียนทับด้วยเวลาคอมพิวเตอร์

24.3 ก่อนนำไปใช้กับคนไข้จริง

คู่มือนี้พาไปถึงระบบที่ทำงานได้บนโต๊ะ ยังไม่ใช่ระบบที่พร้อมใช้กับคนไข้ สิ่งที่ต้องทำเพิ่มอย่างน้อย

  • ต่อ HIS จริงผ่านสิทธิ์ที่ได้รับอนุมัติ พร้อมช่องทางพิมพ์มือสำรอง
  • ทดสอบคู่ขนานกับการจดมือ อย่างน้อยหนึ่งสัปดาห์ เทียบค่าทุกใบ
  • แผนรับมือเมื่อระบบล่มระหว่างคลินิก — ต้องไม่ทำให้คนไข้รอ
  • ผ่านการพิจารณาของคณะกรรมการที่เกี่ยวข้องตามระเบียบของโรงพยาบาล
